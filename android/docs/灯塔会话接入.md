# 灯塔功能会话

安卓「功能」列表新增「灯塔」原生会话，入口和返回继续使用现有会话导航。进入后直接展示排行榜，点击作品查看详情，详情内的追剧／追综日历入口直接弹出官方排期图片。

## 服务端入口配置与首页缓存

灯塔入口由 `GET /api/chat/sessions?client=android` 与普通会话一起下发，安卓不再自行添加入口。服务端读取 `sys_config` 的 `chat.android.sessions` 配置；启动时由 `schema.sql` 幂等初始化，已有配置不会被覆盖：

```json
[
  {
    "id": "local-dengta",
    "title": "灯塔",
    "kind": "dengta",
    "preview": "影视榜单 · 剧集详情 · 追剧日历",
    "enabled": true
  }
]
```

- `id` 保留历史值以兼容已有缓存与置顶记录；该标识现在由服务端配置，保持稳定即可。
- `title` 用于首页会话名称和灯塔榜单页面标题，`preview` 用于首页摘要，`kind=dengta` 对应现有原生页面。目前原生配置仅支持该类型。
- 设置 `enabled=false` 或从数组移除后，下次成功同步会同时移除页面入口和缓存中的对应记录。无需重新打包安卓。
- 原生入口没有消息活跃时间，仍与其他会话一起按安卓的置顶顺序、最近消息时间和 ID 排序。
- 未声明 `client=android` 的会话请求及通用 WebSocket 会话推送保持原有协议。安卓收到 `chat.sessions` 时重取完整安卓列表，避免不含原生入口的推送覆盖配置。

首页功能、系统两类会话共用 `SessionListCache`，按服务器和账号保存完整展示快照，包含入口、标题、摘要、未读数和排序所需时间。冷启动先在 IO 线程恢复快照，再发起会话列表请求；缓存恢复前不单独绘制本地入口，无缓存时等待首个服务端结果。有缓存时刷新期间继续显示缓存，请求失败保留已有内容；成功后更新页面，并原子写回完整快照。管理入口已有的有效摘要在服务同步前继续沿用缓存，同一列表内容不重复写盘。

## 数据接入

依据用户提供的《详情页与追剧日历逆向报告.md》与 `fetch_detail.py`，并读取脚本依赖的 `fetch_webcasts.py` 及已保存的接口响应确定字段结构。安卓通过独立 OkHttp 客户端直接读取灯塔公开 H5 接口，不传送葫芦娃登录令牌，榜单与详情数据链路保持直连，首页入口配置由葫芦娃服务端下发。

| 接口 | 版本 | 使用位置 |
| --- | --- | --- |
| `mtop.alipictures.gravitywave.media.config.get` | `3.0` | 分类下的子类与指标 tab（剧集／综艺／动漫各自的栏目） |
| `mtop.alipictures.gravitywave.media.rank.list` | `3.0` | 日榜、日期及选定的子类与指标 |
| `mtop.alipictures.gravitywave.media.get` | `1.0` | 基础信息、核心播放指标、高光时刻、平台热度、走势、日历图片 |
| `mtop.alipictures.gravitywave.media.platfom.playrule.list` | `1.0` | 更新规则，仅在 `hasPlayRule=true` 时读取 |

`platfom` 是上游接口的实际拼写，不能修正为 `platform`。

### 榜单分类与指标（与网页版对齐）

灯塔网页版 `variety-show-list.html` 的筛选由配置接口下发，分类 code 与子类 code 都不连续，不能按「1/2/3」自行假设：

| configCode | 分类 | 子类 typeCode（默认加粗） |
| --- | --- | --- |
| `1` | 剧集 | **`12` 全部**、`1` 电视剧、`2` 网剧 |
| `2` | 综艺 | **`34` 全部**、`3` 综艺、`4` 网综 |
| `3` | 动漫 | `5` 动漫（`show=false`，只有平台热度） |

指标的 `platformCode` 同样来自配置：剧集为 `beaconmarketshare_play_vv`（正片播放）、`episodeaverageplay_vv`（集均播放），综艺为 `beaconmarketshare`（播放市占），动漫只有各平台热度（`youku` 等）。

早期安卓版本把「剧集／综艺／动漫」直接当作 `typeCode` 传给接口，且固定使用「正片播放」，导致「全网正片播放量」只统计电视剧（约 1.48亿），而网页版「全部」合并剧集与网剧（约 2.20亿）。同时 `typeCode=2` 在接口里是「网剧」，被误标为「综艺」。现在分类、子类、指标都按配置渲染，默认停在第一个可见子类，与网页版一致。

### 数值口径

- 正片播放榜：主值为 `vvCntWithUnit`，副标题为市占率 `columnValue1`；只有该榜有持续累加的播放次数，因此只有它显示 `+xxx` 增量。
- 集均播放榜：主值 `averageCntWithUnit`，副标题给更新进度与 `fixedDateStr`（集均数据按固定日统计，不随时间累加）。
- 播放市占榜：主值为 `columnValue1` 百分比，`cnt` 用于比例条。
- 平台热度榜：主值为 `columnValue1`，单位取 `cntWithUnit.unit`，没有播放次数与市占率。
- 大盘总量 `market.vvCnt` 只有正片播放榜下发，其它榜单不显示该区块。

使用公开 H5 的 `appKey=12574478`。首次请求建立匿名 Cookie 会话，之后按 `MD5(token + "&" + t + "&" + appKey + "&" + data)` 签名；遇到令牌过期重新建立会话并重试一次。Cookie 仅保存在客户端内存，不需要第三方账号。保留系统 TLS 证书和主机名校验，不沿用参考 Python 脚本关闭证书校验的写法。

详情固定携带 `mediaId`、`dr="[]"`、`patternName="BEACON_MEDIA_DETAIL_FILM"` 和 `patternVersion="2.0"`。按 `layers[].style.title` 与 section 内容识别模块，跳过 `dataPresent=false` 的 section，不依赖固定 section 下标。

## 页面行为

- 排行榜支持日期选择、剧集／综艺／动漫切换、子类与指标切换。子类（全部／电视剧／网剧等）和指标（正片播放／集均播放／播放市占／平台热度）都由配置接口下发，与网页版 tab 一一对应，不再写死。取消会话标题栏的手动刷新按钮；今日榜单可见时约每3秒自动请求一次，持续更新时携带 `isLoop=true`。请求串行执行，进入详情、追剧日志、退出会话或应用转入后台时停止轮询；历史日期只在进入或切换条件时获取。
- 自动更新保留当前列表和滚动位置，不反复显示加载条。大盘总播放量和每部作品的播放量按前后两次同一日期快照的原始数值计算差值；在数值上方短暂显示 `+xxx`（负向修正显示负数），约2.3秒后淡出。首次加载、新增榜单项、切换子类／指标／日期及跨日数据不计算增量，集均、市占和平台热度视图不显示播放次数增量。增量区预留固定高度，避免列表抖动。
- 详情展示最新快照，与历史榜单的选定日期分开。播放量、市占、累计播放、集均播放、平台热度和走势图全部取真实响应；缺失字段显示缺失状态，不补演示值。
- 播放与热度曲线读取 `chartDataVO.lines`。可选择曲线和日期查看数值，当日尚未结束的末段用虚线区分，平台热度不跨平台混算。
- 排行榜顶部不再显示「排行榜／追剧日志」切换栏。详情页直接显示「追剧日历」入口，点击后在当前页面弹出日历图片，不再跳转到日志页。
- 日历直接读取 `extra.releaseCalendar`，不从更新规则推算日期、集数或图片地址。`extra.bigType.value=VARIETY` 时入口显示「追综日历」。接口未提供图片时不显示入口；有图时支持原图全屏、双指缩放、拖动和重置缩放。
- 更新规则加载失败只影响规则卡片，已获取的详情和日历仍可查看。榜单、详情刷新失败时保留上次内存快照并标明状态。
- 收藏、观看集数和最多160字的观剧感受按当前葫芦娃服务器及账号存入本机 SharedPreferences。记录时间使用设备当前时间；取消追剧保留历史日志。日志不会上传到灯塔，也不自动同步到其他设备。

## 代码位置

### 官方品牌图标

会话列表和灯塔页面标题栏共用官方客户端下载页的 Logo，保留原始配色，以圆角方式展示。图片随 App 打包，显示时不依赖网络。

### 接入文件

| 文件 | 职责 |
| --- | --- |
| `data/DengtaRepository.kt` | MTOP 请求、Cookie、签名、令牌刷新与取消请求 |
| `data/DengtaModels.kt` | 榜单、配置化详情、指标单位、走势图与个人记录模型 |
| `data/DengtaJournalStore.kt` | 按服务器与账号隔离的本机持久化 |
| `DengtaViewModel.kt` | 页面状态、请求切换、快照、追剧与记录操作 |
| `ui/DengtaScreen.kt` | 会话框架、排行榜、筛选、日期选择与公共组件 |
| `ui/DengtaDetailScreen.kt` | 详情、核心指标、平台热度和真实走势 |
| `ui/DengtaJournalScreen.kt` | 追剧列表、个人日志、日历预览与图片缩放 |

首页入口配置由服务端 `AndroidSessionService` 下发，`HuluwaRepository.kt` 请求完整安卓会话列表，`Models.kt` 解析摘要并区分入口来源与原生导航，`HuluwaViewModel.kt` 和 `SessionListCache.kt` 统一恢复、更新及保存展示快照。`HuluwaRoot.kt` 和 `Components.kt` 负责原生导航与图标接入。
