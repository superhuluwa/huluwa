## 1. 签名服务

### 1.1 接口

```
GET  http://<host>:8901/health     健康检查（会真实签一次名）
GET  http://<host>:8901/info       环境信息
POST http://<host>:8901/sign       生成签名头
POST http://<host>:8901/verify     端到端自检
```

### 1.2 `/sign` 请求/响应

```bash
curl -X POST http://123.57.172.104:8901/sign \
     -H 'Content-Type: application/json' \
     -d '{"url":"https://api5-normal-sinfonlineb.fqnovel.com/reading/bookapi/search/tab/v?aid=8662&query=test"}'
```

### 1.3 签名与 URL 的绑定规则（实测）

| 维度 | 结论 |
|---|---|
| 绑定 path | 是 |
| 绑定 **全部** query 参数（含 `_rticket`） | 是 |
| 绑定 host | **否**（sinfonlinea ↔ b 互换仍有效） |
| 有效期 | **> 1 小时**（实测 61.8 分钟后仍有效） |
| 字节完整性 | 全字节校验，任意改动即失效 |

**因此**：每次请求必须先构造完整 URL → 再签名 → 再发送。不能预先签名复用不同 URL。

### 1.4 各接口实际需要的头（实测）

| 接口 | 不带头 | 只 `Medusa+Helios` | 只 Gorgon 4 个 | 全 6 个 |
|---|---|---|---|---|
| `search/tab` | ✗ 0 字节 | **✓ 81,449** | ✗ 0 | ✓ 79,512 |
| `video_detail` | ✗ 0 字节 | **✓ 146,228** | ✗ 0 | ✓ 146,207 |
| `video_model` | ✗ 0 | ✗ 0 | ✗ 0 | ✗ 0（见第 4 节） |

**结论**：真正门槛是 `X-Medusa` + `X-Helios`；Gorgon 系列（`X-Gorgon`/`X-Khronos`/`X-Argus`/`X-Ladon`）对这三个接口**无贡献**。

> 注：为降低出错概率，建议仍然带全 6 个头——实测带全无副作用。

## 4. ⚠️ 待排查：`video_model` 环境差异

这一节是**需要服务器端 AI 继续验证的核心问题**。

### 4.1 现象

**同一个 vid、同一套参数**，在两个环境下结果不同：

| 环境 | 结果 |
|---|---|
| 本地雷电模拟器（LDPlayer，`SM-S9310`） | ✅ `code=0`，**5,492 字节**，拿到 `main_url` |
| 远端 redroid（`123.57.172.104:8901`，`redroid14_x86_64_only`） | ❌ **0 字节**（无 code，非 JSON） |

> 时间线：2026-11-05 10:06 本地成功；同日 10:30 之后远端始终失败。

### 4.2 已排除的可能（都有实测数据）

| # | 假设 | 测试方法 | 结果 |
|---|---|---|---|
| 1 | 签名缺失/错误 | 5 种头组合对比 | 全 6 个也返回 0 → **不是签名问题** |
| 2 | 参数不全 | 19 种组合（含源码里的 `video_platform`/`device_level`/`video_id_type`） | 全部 0 |
| 3 | 用错 series_id | 分别用 vid 和 series_id | vid 更接近（code=0 但空），series_id 报 101113 |
| 4 | host 不对 | `sinfonlinea` 和 `sinfonlineb` 都测 | 都是 0 |
| 5 | vid 失效 | 换 4 个不同 vid（含刚搜索到的新鲜 vid） | 都是 0 |
| 6 | 路径形态 | `/video_model/v`、`/v1`、`/v2`、`/v`、`/v:version/` | 全部 0（只有 `/video_model` 无后缀返回 18 字节 404） |
| 7 | 需要登录 | `user_is_login=0` 和 `1` 都试 | 都是 0（且本地也未登录却成功） |
| 8 | source 值 | 0/1/2/3/4 全试 | 都是 0 |
| 9 | 网络/服务异常 | 同环境测 `search/tab`、`video_detail` | **都正常**（72KB / 146KB）→ 服务健康 |
| 10 | **用错 ID 类型** | 从 `video_detail` 的 `dir_data.item_list` 取 6 个分集 `video_id` 逐个测 | **全部 0** → 不是 ID 类型问题 |

> 第 10 项是重点：`video_detail` 能返回 73–84 个分集，每项结构为
> `{"video_id": "7611102984516160574", "need_unlock": false}`。
> 用这些分集 `video_id` 调 `video_model` 同样返回 0，
> 这**彻底排除了「搜索结果的 vid 与分集 id 不是一回事」这个假设**。

### 4.3 剩余怀疑方向（按可能性排序）

**方向 A：设备指纹差异导致服务端拒绝（可能性最高）**

- 本地：`SM-S9310`（真实三星机型字符串）
- 远端：`redroid14_x86_64_only`
- 签名虽由各自 App 生成、理论自洽，但 `video_model` 可能对设备类型有额外校验
- **验证方法**：把远端 App 上报的 `device_type` 改成 `SM-S9310`（如果容器可改），重测

**方向 B：App 前置状态不同**

- 本地成功时，App 前台是 `ShortSeriesActivity`（短剧页），可能已建立播放会话
- 远端 App 可能停在首页，未初始化播放模块
- **验证方法**：在远端容器里让 App 进入短剧播放页，再调接口

**方向 C：需要 Cookie / 会话态**

- 源码 `VideoRecBookDataHelper` 里有 `CookieManager.getCookie(...)` 调用
- 但该方法用途不明确，**不能证明** `video_model` 必需 Cookie
- **验证方法**：抓取 App 真实请求头，看是否有 Cookie

**方向 D：`dir_data.item_list` 为空导致**

- 步骤 2 的 `item_list` 实测为空数组，可能意味着剧集数据未正确加载
- `video_model` 可能依赖该状态
- **验证方法**：先解决 item_list 为空的问题

### 4.4 建议的排查步骤（给服务器端 AI）

**第一步：抓 App 真实请求（最直接）**

在远端容器内 hook App 的网络层，让它自己发一次播放请求，对比我们构造的 URL：

```javascript
// frida 脚本
Java.perform(function () {
    var H = Java.use('com.bytedance.frameworks.baselib.network.http.ok3.impl.OkHttp3SecurityFactorInterceptor');
    H.intercept.implementation = function (chain) {
        var url = '';
        try { url = String(chain.request().url().toString()); } catch (e) {}
        var hs = '';
        try {
            var hdrs = chain.request().headers();
            var names = hdrs.names();
            var out = [];
            for (var i = 0; i < names.size(); i++) {
                out.push(names.get(i) + ': ' + hdrs.get(names.get(i)));
            }
            hs = out.join('\n');
        } catch (e) {}
        if (/video_model|video_tab/.test(url)) {
            send({url: url, headers: hs});
        }
        return this.intercept(chain);
    };
});
```

然后手动在 App 里点开一个短剧播放，抓取完整 URL 和请求头。

**第二步：逐字段对比**

拿到真实 URL 后，与自己构造的 URL 做逐参数 diff，找出差异。

**第三步：验证设备指纹假设**


如果与 `SM-S9310` / `SAMSUNG` 差异大，尝试改容器属性后重启 App 重测。

## 5. 完整可运行代码

```python
# -*- coding: utf-8 -*-
"""红果 搜索 -> MP4 播放地址 完整实现"""
import json, time, urllib.parse, urllib.request, gzip

SIGN_SERVER = "http://123.57.172.104:8901"
HOST = "api5-normal-sinfonlineb.fqnovel.com"
UA = ("com.phoenix.read/73932 (Linux; U; Android 14; zh_CN; SM-S9310; "
      "Build/UQ1A.240205.06091433;tt-ok/3.12.13.20)")

DEVICE = {
    "device_id": "305040037566937",
    "iid": "305040037571033",
    "cdid": "432b64a9-68af-457b-b8db-16032c6d6427",
    "device_type": "SM-S9310",
    "device_brand": "SAMSUNG",
    "channel": "vivo_8662_64",
}
COMMON = {
    "device_platform": "android", "aid": "8662", "app_name": "novelread",
    "version_code": "73932", "version_name": "7.3.9.32",
    "manifest_version_code": "73932", "update_version_code": "73932",
    "os": "android", "ssmix": "a", "language": "zh",
    "os_api": "34", "os_version": "14",
    "resolution": "1440*2560", "dpi": "640", "ac": "wifi",
    "host_abi": "arm64-v8a", "dragon_device_type": "phone",
    "user_is_login": "0",
}


def _request(path, extra, timeout=45):
    """构造 URL -> 签名 -> 请求 -> 返回 JSON"""
    p = dict(COMMON); p.update(DEVICE); p.update(extra)
    p["_rticket"] = str(int(time.time() * 1000))
    url = "https://%s%s?%s" % (HOST, path, urllib.parse.urlencode(p))

    # 1) 取签名
    body = json.dumps({"url": url}).encode()
    req = urllib.request.Request(
        SIGN_SERVER + "/sign", data=body,
        headers={"Content-Type": "application/json"})
    with urllib.request.urlopen(req, timeout=90) as r:
        sig = json.loads(r.read())

    # 2) 带签名请求
    h = {"User-Agent": UA, "Accept-Encoding": "gzip"}
    h.update(sig)
    req2 = urllib.request.Request(url, headers=h)
    try:
        with urllib.request.urlopen(req2, timeout=timeout) as r:
            raw = r.read()
    except urllib.error.HTTPError as e:
        raw = e.read()
    if raw[:2] == b"\x1f\x8b":
        raw = gzip.decompress(raw)

    if not raw:
        raise RuntimeError("空响应（签名未被接受或参数不全）")
    return json.loads(raw)


def search_videos(query, offset=0):
    """步骤1：搜索，返回 video_data 列表"""
    j = _request("/reading/bookapi/search/tab/v", {
        "query": query, "offset": str(offset), "count": "0",
        "bookshelf_search_plan": "4", "bookstore_tab": "-1",
        "search_source": "1", "use_correct": "true",
        "is_first_enter_search": "true",
    })
    out = []
    for tab in (j.get("search_tabs") or []):
        for it in (tab.get("data") or []):
            for vd in (it.get("video_data") or []):
                if vd.get("vid"):
                    out.append({
                        "vid": vd["vid"],
                        "series_id": vd.get("series_id"),
                        "episode_cnt": vd.get("episode_cnt"),
                        "duration": vd.get("duration"),
                        "book_id": it.get("book_id"),
                    })
    return out

def video_play_url(vid, all_definitions=False, extra_params=None):
    """步骤3：拿播放地址

    Args:
        vid: 单集 vid（注意：不是 series_id）
        all_definitions: True 返回多清晰度
        extra_params: 额外参数 dict，用于排查

    Returns:
        dict 或 None
    """
    params = {
        "video_id": str(vid),
        "source": "0",
        "need_all_video_definition": "true" if all_definitions else "false",
    }
    if extra_params:
        params.update(extra_params)

    j = _request("/reading/bookapi/video_tab/video_model/v", params)

    if j.get("code") != 0:
        return {"error": j.get("message"), "code": j.get("code")}

    d = j.get("data") or {}
    model = d.get("video_model")
    if isinstance(model, str):
        model = json.loads(model)
    model = model or {}

    return {
        "expire_time": d.get("expire_time") or model.get("url_expire"),
        "authorization": d.get("authorization"),
        "video_list": model.get("video_list") or [],
        "fallback_api": (model.get("fallback_api") or {}).get("fallback_api"),
        "duration": model.get("video_duration"),
    }


def download_mp4(main_url, out_path, chunk_size=1024 * 1024):
    """步骤4：下载 MP4（无需任何签名头）"""
    req = urllib.request.Request(main_url, headers={"User-Agent": UA})
    with urllib.request.urlopen(req, timeout=120) as r, open(out_path, "wb") as f:
        while True:
            chunk = r.read(chunk_size)
            if not chunk:
                break
            f.write(chunk)
    return out_path
```
