# 安卓「红果短视频」接入

功能入口：葫芦娃 → 功能 → 红果短视频。

支持剧名搜索、加载更多、剧集详情、分集选择、清晰度切换、全屏、自动连播和本地断点续播。
需要解锁的分集会显示锁定状态，不发起播放请求。

## 默认连接

默认签名服务地址为 `http://192.168.3.83:8901`，可在入口右上角「连接设置」修改。
安卓不需要导入设备资料或填写设备 ID。

葫芦娃后端每次请求红果元数据前，先从同一签名服务的 `/info` 读取当前 App 的
`deviceProfile`，使用其中的 `device_id / iid / cdid` 等参数构造完整 URL，再调用 `/sign`。
App 重启、重装或设备 ID 变化后，下次请求会自动使用新的设备信息。
旧版手动导入配置和 `hongguo-device-profile.json` 文件不再作为请求身份来源。

### 签名服务的设备信息

`/sign` 的请求、响应协议保持原样，`/info` 增加 `supportsRecovery: true` 及当前设备信息：

```json
{
  "deviceProfile": {
    "params": {
      "device_id": "当前签名 App 的值",
      "iid": "当前签名 App 的值",
      "cdid": "当前签名 App 的值"
    },
    "user_agent": "当前 App 对应的 User-Agent"
  }
}
```

实际 `params` 还包含应用版本、机型、系统和渠道等公共参数。签名服务通过已附加的同一个
Frida 会话调用 `NetworkParams.addCommonParams()` 获取这些字段，只返回白名单内的设备和应用参数，
不返回 Cookie、会话令牌或完整原始 URL。

配套脚本 [enable_signer_device_info.py](enable_signer_device_info.py) 可为已有 `sign_server.py`
补充自动设备信息和 `POST /recover` 能力，保留现有进程恢复和签名实现。脚本默认备份，重复运行不会重复添加代码：

```bash
python3 enable_signer_device_info.py /path/to/sign_server.py
# 随后重启签名进程；Docker 镜像升级或重建时，也需使用已更新的源文件。
```

自检脚本也默认使用签名服务的当前设备：

```bash
python3 hg_video_check.py --server http://192.168.3.83:8901 --mode chain
```

显式指定 `--device-from-container`、`--device-profile` 和导出 JSON 的参数仍保留供排查使用。

## 播放请求被拒绝时的恢复

`110 / ILLEGAL_ACCESS` 表示红果拒绝本次访问，不能单凭此码判断设备 ID 失效或被封禁。
2026-11-05 的排查中，签名服务 `/health` 正常、设备 ID 正确、搜索正常，但 App 自身和外部请求
均被播放接口拒绝；后台重启 App 后，设备 ID 不变，原视频及葫芦娃播放接口恢复成功。

葫芦娃只在播放接口返回 110 时执行一次恢复：

1. 请求签名服务 `POST /recover`。
2. 签名服务在锁内停止并通过已有 ContentProvider 后台启动红果 App，保留数据和设备身份。
3. 等待初始化后重新附加 Frida，重新取得当前设备和签名状态。
4. 葫芦娃重新取设备资料、构造 URL、签名并重试播放模型一次。

签名服务对并发恢复合并处理，一分钟最多恢复一次；仍被拒绝时显示具体的上游返回码，不循环重启。
恢复过程不打开 App 前台，避免 redroid 的 GPU 渲染崩溃。`/health` 只反映能否生成签名，
不能代替真实播放接口的可用性判断。

## 数据与播放流程

```text
安卓搜索 / 选择分集
  → 葫芦娃后端从签名服务 /info 读取当前设备
  → 葫芦娃后端构造完整 URL
  → /sign 返回签名头
  → 红果搜索、详情及 video_model 接口
  → 安卓拿到各清晰度 URL、spade_a 和加密描述
  → 安卓直接对 CDN 做 Range 请求
  → Kotlin 解包内容密钥、解析 MP4、逐样本 AES-CTR 解密
  → Media3 / Android 解码播放
```

后端不下载或解密视频，不把葫芦娃登录令牌转发给 CDN。
安卓仅把当前请求的数据段解密给播放器；索引在同一播放实例的拖动请求之间复用。

### 安卓实现

- `data/HongguoRepository.kt`：元数据接口和数据模型。
- `HongguoViewModel.kt`：搜索、选集、清晰度、请求取消和连播状态。
- `data/HongguoHistoryStore.kt`：按服务器和账号隔离的分集进度，不保存播放 URL 或密钥。
- `hongguo/HongguoKey.kt`：从 `spade_a` 解包 AES-128 内容密钥，参考 Apache-2.0 的 openhongguo。
- `hongguo/CencMp4.kt`：普通 MP4 的轨道索引、8/16 字节 IV、局部加密、随机位置 CTR 处理。
- `hongguo/HongguoDataSource.kt`：限量下载元数据，直接读取 CDN 媒体；同长度修补加密标记，保持 chunk 偏移。
- `ui/HongguoScreen.kt`、`ui/HongguoPlayer.kt`：原生搜索详情页及 Media3 播放器。

当前支持普通 MP4 的内置 `senc` 索引和 `cenc` AES-CTR。暂不支持分片 MP4、外置辅助加密索引、
密钥轮换和其他加密方式；遇到这些格式会明确报错。ByteVC2 不进入可选清晰度列表，HEVC/H.264
等编码仍取决于手机解码能力。

### 后端接口

以下接口统一要求葫芦娃登录认证，使用既有 `ApiResult` 信封。

| 接口 | 说明 |
|---|---|
| `GET /api/hongguo/settings` | 连接状态和当前设备型号 |
| `POST /api/hongguo/settings` | 保存 `signUrl`，设备资料自动获取 |
| `POST /api/hongguo/settings/sync` | 刷新签名服务当前的设备状态 |
| `GET /api/hongguo/search?query=剧名&offset=0` | 去重后的剧集结果和下一页偏移 |
| `GET /api/hongguo/series/{id}` | 剧集详情及分集目录 |
| `GET /api/hongguo/episodes/{id}/playback` | 当前有效的播放地址和每条流的加密信息 |

原生入口由 `AndroidSessionService` 仅向安卓下发，已有数据库升级后自动出现。
若需修改名称或隐藏入口，可在 `chat.android.sessions` 中显式增加 `kind: "hongguo"` 的条目；
配置 `enabled: false` 会覆盖默认入口。聊天数据结构和归档网页端保持兼容。
