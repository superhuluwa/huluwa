# BT影视安卓搜索会话

安卓「功能」增加 `BT影视`（会话 ID / kind：`btbtla`）。发送片名后，服务端异步搜索，沿用聊天消息持久化、请求幂等与 WebSocket 推送机制，返回「封面 + 片名 + 年代 / 类型 / 地区」作品卡片。卡片提供「资源列表」「网站直达」。同名不同详情 ID 分开保留，避免误合并不同年份、季或版本。

## 站点请求链路

站点使用公开 HTML 页面提供数据，无需执行页面中的混淆 JavaScript。

| 请求 | 内容 |
| --- | --- |
| `GET https://www.btbtla.com/search/{UTF-8编码片名}` | `module-item` 中的作品 ID、标题、封面与年代 / 类型 / 地区 |
| `GET /detail/{作品ID}.html` | `module-row-text` 下载条目的资源 ID、完整标题、文件大小 |
| `GET /tdown/{资源ID}.html` | `magnet:?xt=urn:btih:…` 磁力地址 |

详情页一次读取全部资源元数据；点击「复制磁力」或「下载」才读取对应下载页，并在当前弹框回显磁力。服务端缓存最多 512 条成功取得的磁力，目录刷新重新请求详情页。页面请求设有连接 / 响应超时、响应体大小限制，重定向仅允许 BT影视的 HTTPS 域名；接口只接收数字 ID，不接收任意远程 URL。

## 后端接口

沿用项目 API 身份认证与响应信封。

| 接口 | 参数 | 返回 |
| --- | --- | --- |
| `GET /api/btbtla/search` | `q`：片名，1–120 字符 | `kind=btbtla-title`、`btbtlaId`、`title`、`cover`、`year`、`genre`、`origin`、`pageUrl` |
| `GET /api/btbtla/detail` | `id`：作品 ID | 标题、全剧标注集数、资源数量和 `groups` |
| `GET /api/btbtla/magnet` | `id`：下载资源 ID | `id`、`magnet` |

`groups` 按分辨率降序（4320、2160、1440、1080、720 等）排列；清晰度从资源标题识别，修正站点分类标签与实际标题不一致的情况。未标清晰度放末尾。同组内优先展示单集，按季号、集数倒序排列（最新一集在前）；多集分包随后，全集 / 合集以及未标集数的条目靠后。通过标题中的全集、合集、整季、打包、全 N 集、COMPLETE 等标记，以及「第 1 集到全剧集数」的范围识别全集，返回 `collection` 标记。安卓端使用相同排序并兼容旧接口缺少该标记的情况。同集数版本依次展示杜比视界 / HDR、高码、60 帧等标记。集数只识别明确的 `SxxExx`、`第 N 集`、`EPxx`，保留合并集数，不将年份、声道、分辨率或编码器数字当作集号；未知集数集中放末尾。界面保留完整资源标题，便于选择字幕和编码版本。

## 磁力下载

每条资源增加「下载」按钮，先获取该资源磁力，再复用电影港的 `POST /api/chat/subscriptions/magnets/download`，提交 `url`（BT影视详情页）、`title`（作品名）、`magnet`、`quality`（分辨率）和 `episode`（单集或范围）。未标集数、全集与未知清晰度也明确传入标签，避免走电影港详情页的元数据兜底解析。

沿用电影港的默认下载器（qBittorrent、迅雷【飞牛】、迅雷【Win】）、按剧名划分的保存目录、下载任务记录、重复提交拦截、进度查询和结果通知。BT影视会话的「服务设置」可选择共用的默认下载器，并明确提示与电影港共用此设置。

下载时显示「提交中」并禁用重复操作；后端确认成功或任务已存在后，当前资源显示「已提交」，保留弹框便于继续选择其他资源。失败在弹框内展示，按钮恢复后可重试；刷新目录或切换清晰度保留当前弹框内已提交的标记，任务进度仍在「下载」查看。
