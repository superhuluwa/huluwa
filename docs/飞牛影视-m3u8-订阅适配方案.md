日期：2026-10-13。状态：已完成本机代码适配与静态检查；未执行构建、编译、部署、真实下载或飞牛播放验收。工作区原有未提交改动已保留。

## 当前实现与使用入口

1. 在“消息中心 → 电影天堂”搜索电视剧，直接点击卡片“订阅”即可完成订阅，无需填写设置。自动读取完整资源信息、优先选择可识别正片集号的 m3u8 线路，并识别标题中的显式季号（未标明时默认第 1 季）。
2. 首次默认仅记录当前已发布剧集，每 60 分钟检查更新，只下载订阅后新增的剧集；下载默认使用 8 个分片线程、最多 3 次尝试、180 分钟超时、MP4、不限速。已有订阅保留原设置，已暂停时恢复追更；需要调整时到“我的订阅 → 订阅设置”。
3. “播放地址”打开时会拉取完整剧集（卡片只带前 60 条，长剧集必须实时获取），失败则回退卡片数据；默认把 dyttm3u8 线路置顶、剧集按集号倒序（新集在前）。点“离线下载”直接用默认参数入队，不再弹出设置对话框；整条线路都没有集号时（电影）按第 1 集处理，并用所选行的标题/地址定位该版本，预告、花絮不按默认集号入队。参数仍可在“我的下载 → 下载设置”里调整。“我的订阅”合并显示电影港与电影天堂，按首次加入时间排列（先加入的在前），每项标注来源；可在对应条目设置、检查、暂停或恢复。
4. “我的下载 → 离线剧集下载”显示下载百分比、速度及解析、下载、合并、检查归档阶段，每 3 秒自动刷新。进度来自固定版本下载器的轨道输出，多轨道按百分比平均；成功归档前最多显示 99%，完成后显示 100%。未取得进度时只显示处理状态；重试或应用重启会重新获取当前尝试的进度。还可查看脱敏日志、取消等待中或进行中的任务、失败重试和首次跳过剧集的补下载；下载设置支持分片线程、尝试次数、超时、MP4/MKV 与限速。取消只清理正在生成的临时分片，已归档视频不受影响；取消后的剧集不会因订阅巡检自动复活，可手动重试。
5. 暂停订阅会停止检查和领取排队任务，已经开始的一集继续完成，本地媒体文件保留。
6. “我的订阅”“我的下载”“巡检记录”三个页面平级挂在“消息中心”分组下。“巡检记录”把电影港与电影天堂的每次巡检（定时轮询与页面上点“立即检查”）按时间倒序列出：显示时间、来源、剧名、巡检方式、结果（有更新 / 无更新 / 补建基线 / 巡检失败）、新增与提交条数、耗时与说明，并附当轮新增条目的明细（电脑端点开行首箭头查看，手机端卡片内默认展开前 4 条、可继续展开）。记录是当轮快照，删除订阅后历史仍保留；页面可按来源筛选，也可一次性清空。
7. 三种下载统一使用 `/vol1/1000/downloads`，新离线文件直接放在剧名目录，例如 `/vol1/1000/downloads/剧名/剧名 S01E01.mp4`。不创建年份或季号文件夹，季集编号只保留在文件名中。

当前支持项目已有电影天堂 MacCMS 资源，也支持在来源设置中指定其他兼容 MacCMS 采集接口。普通网页的剧集发现、没有 `.m3u8` 后缀的播放接口、特别篇与多集合并编号，需要另行适配，不按列表序号猜测集号。

### 共用下载目录提示不存在或无法写入

旧目录 `/vol1/@appdata/huluwa/data/media` 位于应用数据目录内，部署脚本原先会将其属主设为 `10001:10001`。共用下载目录 `/vol1/1000/downloads` 保留迅雷/qBittorrent 的属主，需要另外授予 UID `10001` 写权限。旧路径可写不能证明新目录已正确挂载并授权。

本轮新增 `scripts/hls-download-dir.sh`，支持 `prepare`（准备目录和 ACL）、`check`（检查容器挂载、配置及实际写入）、`fix`（核对挂载后在线修复 ACL 并检查写入）。授权时优先使用飞牛 TrimACL，其它平台回退到 POSIX `setfacl`。只授权共享根目录及第一层目录，不递归改变已有媒体属主。临时检查文件只在本次创建的 `.huluwa-check.*` 目录内创建和清理。

在包含此脚本的飞牛源码目录执行以下命令，可修复已有容器的目录权限，不需要重新构建镜像或重建容器：

```sh
sudo bash scripts/hls-download-dir.sh fix huluwa-console
```

如果远端源码还没有新脚本，可以先检查容器的挂载，再对已正确挂载的下载目录直接授权：

```sh
sudo docker inspect huluwa-console --format '{{range .Mounts}}{{println .Source "->" .Destination "可写=" .RW}}{{end}}'
# 必须包含 /vol1/1000/downloads -> /vol1/1000/downloads，且可写=true。
# 飞牛 fnOS：POSIX setfacl 在 /vol1 上不生效，必须用 TrimACL 授权。
sudo /usr/trim/bin/trimacl -m a:u:10001:rwxpdDaAeEc:sfd /vol1/1000/downloads
sudo find /vol1/1000/downloads -mindepth 1 -maxdepth 1 -type d \
  -exec /usr/trim/bin/trimacl -m a:u:10001:rwxpdDaAeEc:sfd {} +
# 其它平台（如 CentOS）改用 POSIX ACL：
#   sudo setfacl -m u:10001:rwx,d:u:10001:rwx <目录>
```

如果缺少挂载、挂载来源不一致或挂载为只读，需要按最新 `compose.yaml` 重新创建容器；重启已有容器不会新增挂载。

本轮还修改了 `scripts/deploy-fnos-remote.sh`：授权失败立即停止，重建容器后进行独立的目录写入检查；`HlsDownloadService.java`：错误提示区分目录不存在、不是目录和无法写入，并显示具体路径；本文档及 `DOCKER.md`：补充在线修复方法与飞牛 TrimACL 说明。已在飞牛实机验证：授权后宿主机与容器内 UID `10001` 均可写入共享下载目录，`check` 模式返回通过。

## 推荐方案

在现有 `huluwa-console` Docker 镜像中加入固定版本的 `N_m3u8DL-RE`、`FFmpeg` 与 `ffprobe`，由葫芦娃负责订阅、检查更新、持久化下载队列和通知。先以一个下载工作线程运行，挂载与迅雷、qBittorrent 共用的下载根目录，飞牛影视监控完成文件所在的剧名目录。

对于当前每周一集的需求，先保持一个应用容器。独立下载容器可在任务量增加或需要独立升级下载工具时再拆分。宿主机定时脚本可用于验证一集下载，不作为项目长期订阅入口。

```mermaid
flowchart LR
    A[作品详情页或采集接口] --> B[葫芦娃定时检查]
    B --> C[SQLite 剧集记录与下载队列]
    C --> D[N_m3u8DL-RE 下载与 FFmpeg 合并]
    D --> E[ffprobe 基础检查]
    E --> F[归档到媒体目录]
    F --> G[飞牛影视实时监控更新]
    F --> H[葫芦娃完成通知]
```

| `Dockerfile` | Java 21 运行镜像，UID/GID 为 `10001:10001` | 安装下载工具与媒体工具；根据镜像架构选择官方二进制；固定版本及校验值 |
| `compose.yaml` | 挂载配置数据、Docker socket 和 Frp 目录 | 增加媒体根目录挂载；核实媒体目录写权限 |

现有 `DyttSearchService` 的完整解析结果没有 60 集限制，但聊天卡片的 `toPayload` 最多展示每条线路前 60 项。订阅巡检必须从服务端完整详情获取剧集，不能把聊天卡片载荷作为长期数据源。

现有磁力订阅首次只保存基线，不自动下载已有剧集；现有下载配置只接受 `qb` 与 `xunlei`。HLS 需要独立适配，不能直接把 m3u8 地址交给已有磁力提交方法。

现有磁力默认下载根目录 `/vol1/1000/downloads` 是交给外部下载器使用的宿主机路径。HLS 工具运行于葫芦娃容器时，必须使用容器实际挂载可见的路径。

## 第一集地址与追更来源

一集的 m3u8 通常描述这一集的分片或该集的多个码率版本；它不是电视剧的剧集目录。自动追更应绑定一个可反复访问的作品详情页或剧集 API。

- 来源为项目已有电影天堂资源：使用已有作品 ID，新增按 ID 获取完整详情，选择一条稳定的 m3u8 线路。
- 来源为其他 MacCMS 站点：增加可配置的采集地址和作品 ID，复用剧集解析模型；需用真实返回值验证接口参数及线路内容。
- 来源为普通网页：针对实际详情页编写剧集发现适配器，必要时从每集播放页解析最新地址。
- 只有单集 m3u8：支持手动下载第一集；自动追更要补充剧集列表来源，不根据链接字符串猜测下一集地址。

来源获取和视频下载应分开处理。过期链接重试前重新获取对应剧集地址，不永久保存第一次发现的临时签名 URL。

## 订阅与下载设计

已增加 `HlsSubscriptionService`、`HlsDownloadService` 和 `HlsController`，复用现有鉴权、`ConfigService`、`MessageService` 和消息推送能力。

### 订阅字段

作品 ID、来源类型、详情地址或采集 API、标准剧名、年份、季号、线路、更新检查间隔、启用状态、首次下载范围、最近检查时间、下次检查时间、错误信息。

首次订阅默认记录并跳过当前已发布剧集，只下载后续新增剧集；接口未传首次下载范围时也采用此行为。需要补下载时可显式选择“下载当前已发布剧集，并追后续更新”，并设置“从第 N 集开始”，或通过资源列表手动下载指定集数。

一键订阅自动清理剧名中的季号和更新集数备注，保留作品名称中的普通数字；标准剧名与季号持久化后可在设置中调整。剧集编号从集标题解析；无法确定集号时提示资源不可自动下载，预告、花絮和特别篇不按列表位置自动编号。

### 去重及任务字段

当前采用两张表：`hls_subscription` 和 `hls_download_task`。一集的发现、首次跳过、排队与下载结果保存在同一任务行，减少独立剧集表和任务表之间的状态同步。

- 每个订阅保存作品和指定季的信息；任务使用采集站点与作品 ID 生成的稳定作品键、季号、集号建立唯一约束，单集下载和订阅共用去重。
- 线路与最新地址属于剧集的可更新属性，不因 URL 参数或备用线路改变而重复下载。
- 状态为“等待下载”“下载中”“检查中”“已完成”“失败”“首次跳过”和“已取消”，发现记录不代表下载成功；取消是终态，只有用户显式重试才会重新入队。
- 工作线程以数据库条件更新领取任务，确保手动检查和定时检查同时触发时不重复运行。
- 保存任务尝试次数、下次重试时间、日志路径、最终文件路径、错误信息和完成时间。
- 重启时检查遗留运行任务与目标文件：文件存在且基础检查通过时补记完成，否则重新排队。归档与数据库更新之间崩溃也必须能够恢复。
- 退避重试并设置重试上限；取消订阅保留本地文件，暂停自动检查与新任务提交。
- 「我的订阅」把删除集成到状态徽标：电影天堂显示「已订阅」，点击弹出「是否取消订阅」，确认后删除该订阅及其下载任务记录；电影港点击「已订阅」同样弹「是否取消订阅」，确认后删除该订阅、磁力基线与下载记录（下载器里已提交的任务不受影响）。「暂停追更」按删除处理，不再保留暂停态；残留的「已取消 / 已暂停」项点徽标可直接删除，本地已归档文件始终保留。

### 调度与执行

默认每小时检查一次作品详情，更新周更也允许这种检查频率，不把下载时间硬编码为每周某一刻。检查流程只发现剧集并入队，不在 Spring 定时调度线程中等待下载完成。

默认同时下载一集、每集 8 个分片线程；并发、限速、任务总超时和重试次数可配置。下载器的 HTTP 超时与应用的整集任务超时分别处理。

通过 `ProcessBuilder` 参数列表调用工具，持续消费进程输出并保存脱敏日志。Cookie、签名 URL 等敏感内容不进入通知正文或常规日志。只接收 HTTP/HTTPS 采集接口与 m3u8 直链，规范化输出目录并确保位于媒体根目录内。

按资源需要保存 `Referer`、`User-Agent` 与鉴权配置。对需要额外平台授权的资源，先验证授权与下载工具适配能力。

## 媒体目录与 Docker 挂载

完成文件与迅雷、qBittorrent 使用相同的下载根目录，容器内外归档路径一致。临时分片、合并视频和日志独立放在容器可写层 `/app/.huluwa-work`，不添加绑定挂载或 Docker volume，删除容器即清除，普通重启仍保留。飞牛影视只访问宿主机下载目录，扫描不到容器私有工作区。

```text
仅容器可见 /app/.huluwa-work/<任务ID>/attempt-*/
├── segments/                      临时分片
├── output/                        合并结果，校验后发布
└── download.log                   默认保留 7 天

宿主机与容器 /vol1/1000/downloads
└── 剧名/                          完成文件，供飞牛影视播放
    ├── 剧名 S01E01.mp4
    └── 剧名 S01E02.mp4

容器正式归档目录：/vol1/1000/downloads/<剧名>/
```

`compose.yaml` 已配置以下挂载：

```yaml
# 共享的新下载目录
- /vol1/1000/downloads:/vol1/1000/downloads
# 旧目录保留只读访问
- ${HULUWA_MEDIA_DIR:-./data/media}:/media:ro
```

需更新镜像并重新创建容器以应用代码及挂载变更，保留原有数据目录挂载。本轮未执行这些操作。

宿主机目录必须允许容器 UID `10001` 写入，可以通过现有文件夹权限或组授权处理；不对整个媒体库递归修改所有者。飞牛影视还需要在“系统设置 > 应用 > 影视”中获得该宿主机目录的访问权限。

`S01E01` 为建议采用的常见季集命名。具体剧名刮削匹配与用户播放器兼容性仍要用第一集验收，不能仅凭命名保证识别。

## 下载命令与归档

以下为实现时的命令模板，当前未执行，需先安装工具并注入刚获取的有效 m3u8 地址。

```sh
N_m3u8DL-RE "$M3U8_URL" \
  --save-name "剧名 S01E01" \
  --save-dir "/app/.huluwa-work/1/attempt-1-example/output" \
  --tmp-dir "/app/.huluwa-work/1/attempt-1-example/segments" \
  --auto-select \
  --thread-count 8 \
  --download-retry-count 3 \
  --mux-after-done "format=mp4:muxer=ffmpeg" \
  --ffmpeg-binary-path /usr/bin/ffmpeg
```

实现时根据所固定版本的 `--help` 复核参数。首选保留源编码并合并封装，不默认转码；需要支持其他封装时允许配置 MKV。合并成 MP4 本身不保证视频编码一定能在每个客户端直接播放。

归档前检查退出码、最终文件是否存在及大小，使用 `ffprobe` 检查媒体流与时长，并结合下载器分片数量检查。基础探测不能证明全片没有损坏，第一集仍需实际播放验收。

完成检查后，先从私有工作区复制到剧名目录下 `.huluwa-publish-<任务ID>-<随机ID>.part`，完整写入后在目标目录内通过硬链接原子发布 MP4/MKV，拒绝覆盖同名文件，再移除复制残片及私有工作副本。飞牛扫描范围内不会出现未完成的 MP4/MKV；下载器元数据、日志和分片均留在容器内。随后写入成功状态并通知用户。媒体根目录仍需支持目录内硬链接，私有工作区和媒体目录无需在同一文件系统。

应用启动时与每小时维护时，都会回收闲置分片、半成品、无关联任务目录、过期日志和本下载器命名的 `.part` 残片；维护与下载共用单线程，在两集之间执行。日志默认保留 7 天，可通过 `HULUWA_HLS_LOG_RETENTION_DAYS` 调整，最少 1 天。升级时，原共享 `.huluwa-work` 内仍有任务记录的未过期日志会迁入私有目录并更新日志路径，旧工作副本随后删除；迁移失败时保留源日志以便下次继续。旧只读 `/media` 挂载不做清理。容器重建后，持久化队列会重新下载未完成任务，已归档文件仍在宿主机下载目录。

## 飞牛影视入库

给下载根目录下的剧名目录授权，在影视中创建或编辑媒体库选择对应目录，并打开“实时监控媒体文件更新”。官方说明新增或变更文件会自动更新媒体库，因此第一版优先使用文件监控机制。

若用户当前版本或具体存储方式监控不生效，先核实路径权限并手动扫描验证；是否接入额外刷新接口取决于实际版本和可用接口，不预设一个未经验证的刷新 API。

## 实施顺序与验收

1. 取得第一集 m3u8、作品详情页或采集来源、真实媒体目录，确认资源能够下载与正确编号。
2. 实现手动单集下载、状态记录、归档命名和媒体目录挂载；验收第一集在飞牛影视中的识别与播放。
3. 新增按作品 ID 获取详情、订阅巡检、首次补下载、去重和失败重试；接通电影天堂卡片及订阅管理页。
4. 验证同一集地址变化不重复下载、失败不会被标为成功、容器重启恢复、前端展示截断不漏集、未完成文件不进入媒体库。

遵循项目规则：未经用户明确要求，不运行构建、编译、打包、安装或其他构建验证流程。

本次已适配 Java/Vue/Docker 代码与部署配置。已通过 8 个 Vue 组件及脚本静态解析、30 条 SQL 语句静态检查、SQLite 重复初始化、季集去重、暂停领取、领取幂等及重启恢复检查，3 个部署脚本通过静态语法检查。两个架构的下载器包 SHA-256 已与官方发布元数据核对。新增 JUnit 回归用例尚未执行。未执行构建、编译、部署或下载播放验证，当前线上容器仍是原版本。
