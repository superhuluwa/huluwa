# 懂片帝接入说明

懂片帝（`dongpian19.com`，备用域名 `dongpian.ai`）是「按片名搜索 → 多播放源」的影视聚合站，
形态与电影天堂接近：搜索返回作品卡片，每部作品下有多条播放线路，每条线路是各集的视频直链，可能是 m3u8、MP4 或无扩展名的视频地址。

本站没有公开 API 文档，接口是从其 Web 前端包里还原出来的。

## 接口清单

下列接口都要求 HMAC-SHA256 签名；官方线路兑换还必须携带网站访客会话。

| 用途 | 方法与路径 | 关键返回 |
| --- | --- | --- |
| 访客会话 | `POST /v1/users/anonymous` | 请求体 `{anonymous_id: "web_<UUID>"}`；响应设置 `ai_movie_session` Cookie |
| 搜索 | `GET /v1/browse/catalog?q=片名&limit=20` | `cards[]`：作品卡片 |
| 详情 | `GET /v1/catalog/{作品ID}` | 海报 / 年份 / 地区 / 类型 + `episodes[]`（每集带 `token`） |
| 播放解析 | `GET /v1/playback/resolve/{该集token}` | `line_options[]`：该集全部线路 |
| 官方线路兑换 | `POST /v1/playback/resolve-line` | 请求体 `{ticket, episode_token}`；成功返回 HTTP 201 与 `line` |

另有 `/v1/playback/episodes/{token}` 返回分集 + 线路的组合，本项目没有用到。

## 请求签名

签名算法在前端包 `assets/movie-card-runtime-*.js` 的 `Ta()` 函数里，
密钥 `Jo` 硬编码在同文件的 `Aa()` 附近。

```
signature = HMAC-SHA256(secret, METHOD + "\n" + pathAndQuery + "\n" + timestamp + "\n" + nonce)
```

- `METHOD`：实际请求方法（`GET` 或 `POST`）
- `pathAndQuery`：`/v1/...` 开头，含查询串，必须与实际请求逐字一致
- `timestamp`：毫秒时间戳（`Date.now()`）
- `nonce`：16 字节随机数的小写十六进制（32 个字符）
- 输出：小写十六进制

三个头都要带上：`x-ai-movie-timestamp`、`x-ai-movie-nonce`、`x-ai-movie-signature`。

未签名时站点返回 `401 {"code":"invalid_request_signature"}`。

## 访客会话与兑换错误

官方线路只带接口签名时，可能返回 `401`、`code=playback_user_session_required`、
`state=login_required`，并提示“该内容需要登录后播放”。这表示缺少可用的网站会话，
不能直接解释为签名错误、兑换限流或必须登录注册账号。
2026-10-27 排查《嫁金钗》第 19 集「1080P-官方Z」时，先初始化访客会话再携带 Cookie，
兑换返回 `201` 并取得 MP4 地址。

后端在兑换前按需初始化访客会话，通过服务实例私有的 `CookieManager` 接收、复用 Cookie，
同一实例重建会话时沿用同一个 `anonymous_id`。收到明确的会话错误后，最多重建并重发一次，
重发时重新生成签名；并发请求复用已经恢复的会话。Cookie 不写入日志、数据库或媒体下载请求。

错误提示保留站点 `message`、HTTP 状态、`code` 与 `state`，分别识别签名、会话、等级限制和限流。
兑换只对限流、网络及服务端临时故障退避重试，最终异常直接传给下载任务，
不再被“这一集在该线路上没有可播放的地址”覆盖。主动解析接口同样返回具体原因。
其他登录或等级专属线路仍受站点实际权限规则约束，恢复访客会话不会解除这些限制。

## 线路的两类形态

`line_options[]` 里每条线路有 `url` 与 `resolved`：

1. **可直接播放**（`resolved: true`，`url` 是 `http(s)://…m3u8`）：第三方资源站直链，
   可播放、复制和离线下载。
2. **需兑换**（`resolve_required: true`，`url` 是 `resolve://av_…` 票据）：站点官方线路，
   调用兑换接口时去掉 `resolve://` 前缀，并传入该集自己的 `episode_token`。
   点选线路仅展示已经更新的剧集；第一集同样不预兑换。
   用户点击「解析」或提交下载后，才获取该集的真实地址。
   可否兑换受站点当前的登录、等级、额度及频率规则约束。

官方兑换结果按 `line.resolved=true` 与绝对 HTTP(S) 地址识别，不能要求 URL 含 `.m3u8`。
2026-10-27 排查《狂飙》第 1 集时，官方 Z 返回 `url_kind=mp4`，地址却以 `.jpg~…image.image` 结尾，
媒体内容的文件头为 MP4 的 `ftypisom`；官方 B 返回无扩展名直链，爱奇艺返回 m3u8，三条兑换均为 HTTP 201。
原先的 m3u8 后缀校验会丢掉前两条成功结果，继而误报「兑换配额已用完」。

安卓端对这些视频直链提供播放、复制和离线下载；没有地址的剧集也显示「离线下载」按钮。
列表依据 `current_episode_count` / `available_episode_count` 展示已更新的分集，不显示未来占位集。
打开或刷新列表时重新取得更新集数，未解析条目保留在列表中，地址为空不代表尚未更新。

点击「解析」或执行下载任务取得的地址，按作品 ID、集标题、线路名写入 `dpd_episode_link`，
永久保存、不设置有效期；再次打开列表会批量读回这些链接，服务重启和分集 token 轮换后仍可复用。
此表与第三方线路的 6 小时 `dpd_episode_cache` 分开，短期缓存到期不影响永久记录。

## 不同集的线路覆盖范围

作品线路清单只从首集探测，表示候选播放源，不保证每个已更新剧集都包含同一条线路。
2026-10-28 排查《玉簟秋》时，首集同时提供 `4K海外-官方C` 和 `海外-官方C`，
但第 25、26 集只有普通 `海外-官方C`，对应的 `bytevod-cloudflare-4k` 源并不存在。
第 25 集的普通 C 线路携带访客会话兑换返回 `201`，并取得 m3u8 地址。

下载提交前仅对用户选择的那一集读取线路及票据，不兑换地址。
若该集缺少所选线路，接口返回 `422`，明确剧名、集标题、所选线路及该集实际可选线路，
避免先显示“已添加”再后台失败；其他集不受影响。
历史队列中的缺源任务同样保留具体原因，并直接结束此次任务，不反复自动重试。
4K 和普通线路是不同的播放源，缺少 4K 时由用户切换线路，不自动降低画质。

## 为什么线路要懒解析

每条线路的**每一集**都要单独请求一次 `/v1/playback/resolve`（单次约 2–3 秒）。
一部 36 集的剧，只解析 1 条线路要 10 秒左右，全量 23 条线路就是几分钟。

所以：

- `/api/dpd/detail` 只探测第一集，用来拿到**线路名清单**（`dpdLines[].episodes` 为空）；
- 直链线路：`/api/dpd/line` 以 6 并发解析前 12 集，其余后台补齐；
- 官方线路：`/api/dpd/line` 不兑换任何一集，仅读回已更新的分集和永久保存的链接；
- 分集清单不再受原有 150 集后台预解析上限限制，界面标注「已更新 N 集」；
- 点击「解析」时，`/api/dpd/episode` 先查永久记录，没有地址才兑换并写库；
- 点击「离线下载」时，`POST /api/dpd/downloads` 只提交作品 ID、线路、集标题和季集号，
  后端先确认该集提供所选线路，再持久化到现有离线剧集队列；
  轮到任务执行时再查永久记录、兑换缺失地址并保存；
- 新的懂片帝下载任务用 `hls_download_task.api_url=dpd` 标记来源，不混用采集站的数字 ID；
- 普通 m3u8 使用现有分片下载器；无扩展名和图片后缀的链接按文件头识别，
  HLS 交给分片下载器，MP4 流式下载后由 FFmpeg 重新封装，沿用限速、取消、重试、校验及归档；
- 第三方直链保留原有 6 小时缓存，官方票据缓存在内存中；主动取得的链接永久落库。
  作品详情缓存 30 分钟，安卓打开或刷新资源列表时通过 `refresh=true` 获取最新更新集数。

## 维护提示

- **签名密钥轮换**：站点改版后可能出现大量 `401 / 签名校验失败`。此时重新拉取前端包，
  先依据返回的 `code` 区分会话与签名错误；确认为 `invalid_request_signature` 时，
  找到 `movie-card-runtime-*.js` 里的 `Ta()` 与 `Jo`，更新 `DongPianSearchService.SECRET`。
- **域名更换**：改 `DongPianSearchService.BASE_URL` 即可，备用域名 `dongpian.ai` 接口与签名一致。
- **不参与订阅追更**：站点按集下发 `token`，没有稳定的分集地址可比对更新，
  因此懂片帝卡片没有「订阅」按钮，也不进「我的订阅」。

## 与电影港 / 电影天堂的隔离

懂片帝是**独立一套**，不复用另外两个来源的卡片、弹层与载荷结构：

| 层面 | 电影港 / 电影天堂 | 懂片帝 |
| --- | --- | --- |
| 载荷类型 | `playSources` / `magnets` | `kind=dpd-title` / `dpd-detail` / `dpd-line` |
| 标识字段 | `id` / `url` | `dpdId` / `pageUrl` |
| 安卓卡片模型 | `FilmCard` | `DpdCard`（`ChatMessage.dpd`） |
| 安卓弹层 | `AppSheet.Films` | `AppSheet.Dpd` |
| 接口 | `/api/hls/**`、`/api/chat/**` | `/api/dpd/**` |
| 订阅追更 | 支持 | 不支持（站点按集下发 token，无稳定地址可比对） |

懂片帝载荷故意不带 `url`，因此不会被 `ChatMessage.film` 误判成 `FilmCard`。
