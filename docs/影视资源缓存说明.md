# 懂片帝与电影天堂资源缓存

安卓「功能」中的懂片帝和电影天堂参考 BT影视，采用服务端 SQLite 持久化资源快照、打开时先读缓存、后台刷新、App 轮询同步的方式。初次没有缓存时等待第一份目录；再次打开或手动刷新立即显示已有资源。刷新失败保留上次目录并显示重试提示，关闭弹框后后台工作继续，服务重启后缓存仍保留。

## 接口

继续使用现有接口、鉴权和资源字段，新增以下参数与状态：

| 接口 | 作品及线路参数 | 缓存控制与返回 |
| --- | --- | --- |
| `GET /api/dpd/detail` | `resId` | `cachedOnly=false` 返回缓存并启动刷新；`true` 只读缓存；返回 `refreshing`、`refreshError` |
| `GET /api/dpd/line` | `resId`、`line` | 同上；后台补齐期间可不断取得新增的集地址 |
| `GET /api/hls/detail` | `resId`、可选 `apiUrl` | 同上；保存完整 `playSources`，不受聊天卡片 60 集的展示上限限制 |

`cachedOnly` 默认 `false`。安卓刷新期间每 1.2 秒读取一次缓存快照，收到 `refreshing=false` 后停止；同一作品或线路的并发刷新共用一个后台任务。纯缓存请求不会触发目录抓取、分集解析或官方线路兑换。目录刷新与长剧线路解析分用线程池。

## 懂片帝

作品目录保存作品信息、线路名与已更新集数。点选线路时先返回分集快照；初次没有线路快照时先保存全部已更新的分集与已有链接，未解析地址留空，再在后台分批补齐。

第三方线路每批最多解析 6 集，覆盖全部已更新集数；一次分集请求取得的所有第三方直链都按作品、集标题和线路写入 `dpd_episode_link` 永久保存，同时每批更新当前线路快照。已有的短期解析缓存会复用并归档为永久记录，失败项在再次打开或刷新时重试。

官方线路只返回已更新剧集及此前保存的链接，后台不兑换票据。用户主动解析或下载任务执行时才兑换缺失地址；线路缓存读取时也会合并这些新保存的链接。

安卓同步时保留选中线路、已取得地址和下载标记；刷新过程中继续显示旧列表，空地址不会覆盖主动解析取得的链接。作品目录刷新完成后，再同步已打开线路的新集数。关闭弹框或切换作品会取消对应轮询，旧请求不会回填新弹框。

## 电影天堂

完整作品信息、播放源与所有分集地址保存到服务端，缓存键包含规范化后的采集接口地址和作品 ID，避免不同采集接口的相同数字 ID 互相覆盖。安卓打开时显示缓存，在后台刷新期间自动更新当前弹框，并按线路名称保留选择。已有订阅封面回填、下载提交和执行时重新取得有效地址的机制继续沿用。

## 存储

`video_resource_cache` 以 `(source, provider, res_id, line_name)` 为主键；空线路名表示作品目录。表内保存资源 JSON、最后刷新错误和数据更新时间，目录实际变化时才更新数据时间。刷新错误单独保存，不覆盖已有资源。schema v11 幂等建表，旧库启动时自动补入。

懂片帝的永久链接继续使用 `dpd_episode_link`，token 对应的短期解析结果继续使用 `dpd_episode_cache`。BT影视保留原有缓存表及处理流程。
